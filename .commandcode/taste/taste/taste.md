# Taste
- Communicates in Indonesian (Bahasa Indonesia) and expects responses in the same language. Confidence: 0.9
- When presented with multiple-choice design options that include a recommended choice, tends to accept the recommended option (e.g., kanban with arrow buttons over adding a drag-and-drop library, automatic stock reservation on SO approval, full CRUD for activities). Prefers solutions that avoid adding new third-party dependencies. Confidence: 0.7
- Works iteratively through a predefined sprint roadmap and wants the agent to continue to the next sprint (e.g., "lanjut sprint 5", "bisa lanjut?", "lanjut 7") once the current one is verified — expecting each sprint to be implemented end-to-end (backend + frontend + tests + docs) autonomously with minimal direction. Confidence: 0.9
- Values seeders being idempotent (rerunnable via `db:seed`) and test isolation (demo/seed data gated behind an env flag like `SEED_DEMO=false` in phpunit) so seed data never breaks the test suite. Confidence: 0.8
- Periodically asks for a status of remaining/pending work ("sisa pendingan apa saja?") and expects the answer to be grounded in project docs (e.g., `modul.md`) and the actual codebase — including gaps like backend features without UI — rather than a vague summary, so they can pick the next thing to work on. Confidence: 0.7
- Delegates code-implementable pending features (e.g., SO fulfillment, missing reservation UI, user/role management, quotation comparison) to the agent, while explicitly keeping operational tasks — UAT with end users, production deployment, and document approvals — out of the agent's scope for the user to handle themselves. Confidence: 0.6
- Expects completed work to be durably marked/tracked somewhere findable (asked "apakah kamu menandai pekerjaan yang sudah kamu lakukan? di mana kamu simpan?"), not just ephemeral per-session todo lists — wants visibility into where progress is permanently recorded (e.g., README, docs, git history). Confidence: 0.5
